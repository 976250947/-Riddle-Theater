## 2. 当前项目概况

### 2.1 项目名称

谜语剧场——剧情交互游戏平台

### 2.2 当前阶段

当前处于"前后端分离工程化原型 + 可运行剧情引擎 + 数据库化后端"阶段。前端已迁移至 Vue 3 + Vite，后端已迁移至 Express + Prisma + SQLite，项目已具备结构化数据存储与 API 服务能力，但尚未进入生产级部署阶段。

### 2.3 当前定位

当前版本的定位不是完整商业化平台，而是：

- 可演示的前后端分离剧情交互游戏平台原型
- 可持续扩展的多剧本内容容器（故事已入库）
- 可验证 LLM 受控互动模式的实验基座
- 可作为课程、比赛、作品集继续深化的工程基础

### 2.4 当前目标

当前仓库主要服务以下目标：

- 让用户能够在多个题材故事间切换并进入剧情
- 提供固定选项与有限自由输入混合的叙事体验
- 支持结局达成、结局图鉴、回滚、回顾和多周目体验
- 验证“固定剧本骨架 + 受控 LLM 互动”的产品可行性
- 为后续素材接入、创作工具、真实社区和数据能力预留接口

## 4. 核心交互能力

### 4.1 剧情推进模型

项目当前使用 stage / scene 驱动的叙事结构。每个 scene 可以配置：

- 标题与章节标签
- 当前目标与风险 stakes
- public_script
- npcDialogue
- choices
- scene_card
- visual_state
- presentCharacterIds
- characterTopics
- hiddenTruths
- forbiddenReveals

这使得剧情既能按固定剧本推进，也能为探索、对话和自由输入提供受控上下文。

### 4.2 当前互动模式

当前已接入的互动模式包括：

- 固定选项：标准分支推进方式
- 半开放扩展操作：根据当前场景自动生成补充操作
- 自由探索：用于调查、观察、补充线索
- NPC 对话：支持多轮发问与角色回应
- 自由输入：玩家可输入自然语言，由系统进行意图识别并承接到已有分支

### 4.3 当前互动约束

为避免 LLM 叙事失控，当前引擎会提供以下硬约束：

- sceneCard：锁定地点、时间、天气、关系阶段、目标
- visualState：锁定当前视觉语义
- hiddenTruths：模型可参考但不可越界泄露的内容
- forbiddenReveals：明确禁止模型提前说破的剧情信息
- presentCharacters：限制当前场景可参与互动的角色范围

### 4.4 当前限制参数

默认限制如下：

- 每个阶段探索次数上限：3
- 每个阶段对话轮数上限：5
- 本地存档位数量：6
- 结局序列：good / normal / bad / hidden

## 5. 当前技术架构

### 5.1 整体架构

项目采用前后端分离 + 运行时引擎三模块架构：

- **前端（frontend/）**：Vue 3 + Pinia + Vue Router，由 Vite 6 构建
- **后端（backend/）**：Express 4 + Prisma ORM + SQLite
- **运行时引擎（src/）**：纯 JavaScript 模块，包含叙事引擎、演出控制器、LLM 客户端和故事配置

三个模块通过 npm workspaces 统一管理，前端通过 Vite 别名 `@runtime` 直接引用运行时引擎代码。

### 5.2 前端架构

前端已从原生 JavaScript 迁移至 Vue 3 组件化架构。

核心模块如下：

- frontend/src/App.vue：应用根组件与全局布局
- frontend/src/router/index.js：Vue Router 路由配置
- frontend/src/stores/game.js：Pinia 游戏状态管理（剧情推进、演出控制、存档读取）
- frontend/src/stores/auth.js：Pinia 认证状态管理
- frontend/src/views/*.vue：各页面视图组件（首页、剧本库、详情、游玩、结局等）
- frontend/src/services/api.js：统一后端 API 调用封装
- frontend/src/components/*.vue：可复用 UI 组件（Navbar、SaveLoadModal、StoryCard）

### 5.3 内容配置架构

故事内容采用 story pack 配置模型，同时存在本地运行时和数据库两层：

- src/config/story-packs.js：运行时 story pack 注册与统一访问入口
- src/config/stories/*.js：5 个具体剧本内容配置（含阶段、选项、角色、线索、结局等完整数据）
- 后端数据库 Story 表：所有故事的可序列化内容已通过 seed 脚本入库，packData 字段保存完整的阶段树、线索库、角色表等数据

前端展示页面（首页、剧本库、排行榜等）优先从后端 API 获取故事数据，API 不可用时回退到本地运行时导入。

### 5.4 叙事引擎架构

核心引擎位于 src/core/story-engine.js，当前负责：

- 创建初始状态（createInitialState）
- 进入 stage 与构建 VN 对话序列（enterStage -> buildDialogueLines）
- 处理 choice 提交与分支推进（submitChoice -> advanceStage）
- 生成 world state 供 LLM 上下文使用
- 驱动自由探索与 NPC 对话（submitExploreAction / submitDialogue）
- 计算结局与结局元数据
- 状态归一化与回滚（normalizeState / rollbackToCheckpoint）

表演控制位于 src/core/perform-controller.js，实现 WebGAL 风格的 VN 式逐句播放：

- 状态机：IDLE -> TYPING -> WAITING_CLICK -> NEXT_LINE（循环）
- 遇到 choices 标记时进入 CHOICE_GATE 状态，等待玩家选择
- 支持打字机跳过、历史回顾、中途插入新行

### 5.5 后端服务与数据层

后端已从原生 Node.js 文件服务迁移至 Express + Prisma + SQLite 架构：

- backend/src/app.js：Express 应用配置（CORS、JSON 解析、路由挂载）
- backend/src/routes/auth.routes.js：注册、登录、游客认证、token 验证
- backend/src/routes/story.routes.js：故事列表与详情 API
- backend/src/routes/save.routes.js：云存档的存取与列表
- backend/src/routes/comment.routes.js：评论发布与查询
- backend/src/middleware/auth.js：JWT 认证中间件
- backend/prisma/schema.prisma：数据模型定义（User、SaveSlot、Story、Comment）
- backend/prisma/seed.js：从运行时故事配置向数据库种子数据

### 5.6 数据库模型

当前 SQLite 数据库包含以下表：

| 模型 | 用途 | 关键字段 |
| --- | --- | --- |
| User | 用户认证 | username, alias, passwordHash, role (REGISTERED/GUEST) |
| SaveSlot | 云存档 | slotId, storyId, title, payload (JSON), userId |
| Story | 故事目录与内容 | 全部元数据 + packData (JSON，含阶段树、线索库、角色表等) |
| Comment | 评论 | storyId, alias, content, userId |

### 5.7 存档策略

当前同时存在两层存储：

- localStorage：会话自动存档、结局元数据、存档位、LLM 配置

两层存储互为补充，本地存档保证离线可用，云存档支持数据持久化。

## 6. LLM 集成现状

### 6.1 当前接入方式

项目已经具备两类接入方式：

1. 浏览器端直连 OpenAI 兼容接口
2. 通过 /api/llm/chat 走后端代理

### 6.2 当前配置能力

前端设置面板允许用户配置：

- 是否启用 LLM
- baseURL
- apiKey
- model
- temperature
- maxTokens
- 是否流式输出

### 6.3 当前降级策略

当 LLM 未启用或配置不可用时，系统使用内置模板文本与引擎默认反馈，保证核心路径仍可游玩。

### 6.4 当前注意事项

- 直连模式下 API Key 保存在浏览器本地，不适合生产环境。
- 当前 LLM 更多用于增强探索 / 对话反馈，不负责改写主线骨架。
- 当前系统已经通过 sceneCard 和 forbiddenReveals 对模型输出施加限制，但仍需继续补充回归测试。

## 9. 当前不足与边界

当前项目仍有明确边界：

### 9.1 部分平台化页面仍为展示态

社区、创作工坊、个人中心页面已实现 UI，但内容仍以展示型数据为主，尚未形成完整的用户生产内容链路。

### 9.2 数据库为本地 SQLite

当前认证、存档、故事和评论数据已迁入 Prisma + SQLite，但 SQLite 适合单机开发与演示，不适合生产级并发部署。后续如需上线可迁移至 PostgreSQL 等。

### 9.3 美术与音频资源仍在补全

当前仓库已经具备素材生成文档，但背景图、角色立绘、音效尚未批量接入正式运行版本。

### 9.4 游戏运行时仍依赖本地引擎代码

游戏实际运行（状态机、选项推进、结局判定）仍通过前端直接导入 src/ 下的运行时引擎完成，数据库中的 packData 仅用于展示页面。完全后端驱动的游戏运行尚未实现。

## 10. 下一阶段建议

基于当前工程状态，建议下一阶段优先顺序如下：

1. 接入听晚及其他剧本的背景、角色、音效资源
2. 将游戏运行时逐步从前端本地导入迁移到后端 API 驱动
3. 将创作工坊中的演示型工具逐步替换为真实可编辑数据流
4. 将 SQLite 迁移至 PostgreSQL 以支持生产级部署
5. 为剧情引擎和 LLM 边界增加更多自动化测试
6. 逐步把社区、个人页从展示型页面升级为真实功能页面
