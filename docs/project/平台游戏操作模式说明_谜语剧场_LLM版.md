本文档主要描述目标玩法模型，但当前仓库已经有一部分操作模式真正落地，需要先说明当前实现边界：

## 2. 平台定位

“谜语剧场”不是传统数值战斗游戏，也不是单纯的视觉小说阅读器，而是一个：

> **以“剧情体验 + 多分支选择 + 线索收集 + 多结局探索 + LLM 实时生成互动”为核心的 Web 互动叙事游戏平台。**

平台中的剧情体验由两部分共同构成：

1. **预设剧本内容**  
   由作者或策划预先设计世界观、章节主线、关键人物、核心线索、关键节点与结局。

2. **LLM 动态剧情内容**  
   在玩家游玩过程中，系统根据当前章节状态、玩家行为、历史选择、角色关系、线索与道具，实时生成：
   - NPC 对话
   - 场景补充描写
   - 调查反馈
   - 过渡桥段
   - 支线事件
   - 自由输入后的剧情响应
   - 个性化叙事表达

因此，“谜语剧场”的核心不是固定文本播放，而是：

> **在可控世界规则下，由预设主线保证内容质量，由 LLM 增强互动密度、个性化反馈和可玩深度。**

---

## 3. 平台整体玩法闭环

从玩家视角看，完整游玩闭环如下：

```text
进入平台首页
→ 浏览推荐剧本 / 搜索 / 标签筛选
→ 进入剧本详情页
→ 查看背景设定、章节数、分支数、时长、难度、玩法特色
→ 点击“开始故事”
→ 进入章节化剧情页面
→ 阅读当前节点内容
→ 选择固定选项 / 输入自由行动 / 与 NPC 实时对话
→ 系统读取当前世界状态并调用 LLM 生成剧情反馈
→ 更新线索、道具、属性、关系、分支标记
→ 推进至下一节点或动态事件
→ 达成阶段性结果或最终结局
→ 查看结局页、路线图、生成式复盘
→ 二刷、改线、挑战隐藏结局
```

与传统交互叙事不同的是，这个平台在“阅读剧情”和“做出选择”之间增加了一层：

> **世界状态感知 + LLM 实时生成反馈层**

这一层使得玩家不再只能点击预设按钮，而可以在受控范围内获得更自然、更像“在故事中行动”的体验。

---

## 4. 双引擎玩法结构：固定剧本 + LLM 实时生成

为了保证既有叙事质量，又有足够自由度，平台采用“双引擎”模式。

### 4.1 固定剧本引擎负责什么

固定剧本引擎负责不可随意漂移的内容，包括：

- 世界观与题材边界
- 核心人物设定
- 章节顺序与主线骨架
- 关键线索与证据真相
- 强约束事件
- 关键分支节点
- 结局判定规则
- 重要台词、演出桥段、名场面

这部分决定了作品的“可控性”和“叙事品质”。

### 4.2 LLM 引擎负责什么

LLM 引擎主要负责高频互动层，包括：

- 当前场景的细节描写
- 玩家提出的问题的实时回答
- NPC 的个性化回应
- 固定节点之间的自然过渡
- 不影响主线真相的小型支线
- 调查行为的动态反馈
- 多轮问询、试探、欺骗、套话等互动
- 玩家自由输入动作后的叙事响应

这部分决定了作品的“沉浸感”和“活性”。

### 4.3 两者如何协作

最理想的协作方式是：

> **主线由固定剧本控制，局部互动由 LLM 丰富。**

也就是说，平台不是把整部剧本完全交给大模型自由发挥，而是：

- 主线骨架固定
- 关键节点有限制
- 真相不能被模型胡乱改写
- 动态生成内容必须围绕当前状态展开
- LLM 可以生成“过程”，但不能破坏“框架”

这能避免剧情失控、角色性格漂移、结局逻辑崩坏等问题。

## 5. 首页阶段的操作模式

首页承担的是“内容分发”和“进入故事”的职责。

### 5.1 玩家在首页的目标

玩家进入首页后，平台需要在很短时间内让其理解：

1. 这是一个剧情交互游戏平台
2. 剧本类型很多，可自由选择
3. 不只是看故事，还可以通过互动推动剧情
4. 部分剧本支持 LLM 实时对话与动态剧情扩展

### 5.2 首页的主要操作

玩家可执行的行为包括：

- 浏览推荐剧本
- 按题材标签筛选：悬疑、情感、奇幻、科幻等
- 按时长、难度、热度排序
- 查看支持“AI 动态剧情”的剧本标识
- 收藏剧本
- 进入剧本详情页

### 5.3 首页上的“AI 剧情”提示

为了让用户知道平台不仅是普通文字游戏，首页卡片或详情入口建议标注：

- AI 实时互动
- 可自由追问角色
- 支持动态调查
- 支持个性化支线
- 支持生成式复盘

这样能把平台差异化点明确传达给用户。

---

## 6. 剧本详情页的操作模式

详情页是玩家决定“要不要开始玩”的关键页面。

### 6.1 详情页要回答的问题

玩家最关心的是：

- 这是个什么故事
- 适合什么人玩
- 章节多不多、时长多长
- 主要玩法是什么
- 有多少结局
- AI 实时剧情功能会怎么玩

### 6.2 详情页核心模块

详情页建议包含：

1. **封面与标题区**
2. **剧情简介**
3. **剧本信息**
   - 作者
   - 发布时间
   - 章节数
   - 分支数
   - 可解锁结局数
   - 推荐时长
4. **玩法特色**
   - 多结局
   - 推理线索
   - 角色关系
   - AI 动态对话
   - 自由输入互动
5. **章节预览**
6. **玩家评价**
7. **开始故事 / 继续游戏**
8. **AI 玩法说明入口**

### 6.3 AI 玩法说明在详情页的价值

由于很多用户第一次接触“生成式剧情游戏”，详情页最好用简短说明告诉玩家：

- 你既可以点击系统给出的选项，也可以在部分场景中输入自己的行动
- 你可以主动向 NPC 提问
- 模型会结合你已经获得的线索与角色关系进行回应
- AI 生成内容不会脱离世界观与主线真相

这一步很重要，因为它决定玩家会不会尝试更高自由度的玩法。

## 7. 游戏内的核心操作模式

游戏真正的交互发生在章节页 / 节点页中。

从体验上看，这个平台的游戏内操作模式可以概括为：

> **阅读剧情 → 感知当前状态 → 做出行动 → 系统判定 → LLM 生成反馈 → 更新世界状态 → 推进剧情**

和普通剧情游戏相比，区别在于这里的“行动”不只来自固定选项，还可以来自玩家自由表达。

---

## 8. 剧情推进的基本单元：节点

平台建议以“节点”为最小叙事单位。

每个节点通常包含：

- 节点 ID
- 所属章节
- 场景背景图
- 叙事文本
- 角色对白
- 音效 / 演出参数
- 固定选择项
- 自由输入开关
- 可触发的 LLM 任务类型
- 状态更新规则
- 下一节点映射关系

### 8.1 节点驱动的基本交互循环

```text
系统渲染当前节点
→ 展示场景、文字、人物状态
→ 玩家进行操作
   ├─ 点击固定选择
   ├─ 查看线索 / 背包 / 关系状态
   └─ 输入自由行动 / 发起对话
→ 系统读取当前状态并执行规则判断
→ 必要时调用 LLM 生成剧情反馈
→ 写回状态变化
→ 跳转到下一节点或动态节点
```

### 8.2 为什么节点结构适合接 LLM

因为 LLM 最怕“上下文失控”，而节点结构天然提供了边界：

- 当前场景是什么
- 当前可以做什么
- 玩家已经知道什么
- 哪些信息绝对不能提前泄露
- 哪些角色当前在场
- 允许模型生成到什么程度

这使得 LLM 不会在整本剧本范围内无限发散，而是在“当前节点上下文”里受控输出。

---

## 9. 玩家可执行的三种操作模式

为了兼顾可玩性和可控性，建议平台支持三种核心操作方式。

### 9.1 固定选项操作

这是最稳定、最基础的模式。

玩家看到 2~4 个选项，例如：

- 前往案发现场，仔细搜查
- 向附近目击者询问
- 先回旅馆整理线索
- 在巷口等待，观察动静

特点：

- 逻辑清晰
- 节奏稳定
- 便于控制剧情走向
- 适合大部分主线推进

### 9.2 半开放式操作

系统给出若干方向，但允许玩家做轻量自定义，例如：

- 调查目标：`[门锁 / 地面脚印 / 血迹来源]`
- 发问对象：`[警官 / 女主 / 店主]`
- 发问方式：`[直接提问 / 试探 / 诱导]`

本质仍是结构化输入，但比纯按钮更灵活。

### 9.3 自由输入操作

在特定节点开放文本输入框，允许玩家直接输入：

- “我想先检查怀表背面的刻字”
- “我不揭穿他，先顺着他的话往下问”
- “我问她昨晚十一点到十二点在哪里”
- “我把匿名信拿出来观察纸张纤维”

此时系统调用 LLM，对玩家输入做以下处理：

1. 理解玩家意图
2. 判断是否符合当前世界规则
3. 生成角色或系统反馈
4. 决定是否更新状态
5. 决定是否导向新分支或回到主线

这正是平台“像在真实故事里行动”的核心体验来源。

## 10. LLM 实时生成剧情的操作模式

这是在原有平台基础上新增的关键能力。

### 10.1 LLM 在游戏中的主要作用

LLM 不是替代剧本，而是作为“互动叙事放大器”，主要承担以下任务：

- **实时对话生成**：让 NPC 根据当前关系、立场、已知信息作答
- **动态场景反馈**：根据玩家行动生成调查结果、观察细节、环境变化
- **桥接型过渡叙事**：在固定节点之间生成自然衔接内容
- **个性化表达**：同一事件因玩家风格不同而得到不同描述
- **自由行动解释**：把玩家非预设输入转化为合理剧情响应
- **轻支线生成**：在不破坏主线的前提下扩展短支线
- **复盘总结生成**：根据玩家路线自动生成本轮故事总结

### 10.2 哪些场景适合调用 LLM

建议将 LLM 主要用于以下场景：

1. **问话场景**  
   玩家与角色进行多轮问答、套话、施压、试探。

2. **调查场景**  
   玩家自由描述要检查什么，系统生成细节反馈。

3. **支线探索场景**  
   玩家做出主线外的小动作，例如绕路、观察、翻找、试探接触某人。

4. **过场连接场景**  
   主线节点之间需要更自然的叙事过渡时。

5. **个性化复盘场景**  
   游戏结束后生成“你这一轮的故事回顾”。

### 10.3 哪些场景不适合完全交给 LLM

以下内容不建议完全放开：

- 关键真相揭示
- 结局判定
- 核心证据归属
- 世界观基础设定
- 角色关键人设
- 剧情大转折
- 涉及敏感安全审核的开放内容

这些应由固定规则或人工设计控制，LLM 只能在边缘处润色和补充。

## 11. LLM 参与后的游戏内操作流程

当玩家触发 AI 互动时，系统内部流程建议如下：

```text
玩家输入行为 / 提问
→ 前端将输入与当前节点上下文提交给后端
→ 后端读取世界状态
   - 当前剧本与章节
   - 当前节点
   - 玩家已获线索与道具
   - 玩家属性与关系
   - 已解锁 / 未解锁分支
   - 当前角色在场信息
   - 禁止泄露的信息
→ 规则层先做合法性判断
→ 构造提示词并调用 LLM
→ 得到候选剧情反馈
→ 经过一致性检查 / 敏感内容检查 / 状态更新器
→ 返回前端展示文本、选项变化、线索更新、分支结果
```

### 11.1 玩家看到的表层体验

在玩家眼里，这个过程应该非常自然：

- 我问了一个问题
- 角色真的回答了
- 我尝试一个动作
- 系统给出了符合情境的反馈
- 我的行为似乎真的影响了后续发展

### 11.2 系统内部必须做的约束

为了不让模型“胡编”，后端必须先做规则约束，再做生成，而不是直接把玩家输入丢给模型自由写。

## 12. LLM 剧情生成中的状态建模

要让生成内容稳定，平台必须有明确的“世界状态模型”。

### 12.1 世界状态至少包括

- 当前剧本 ID
- 当前章节 ID
- 当前节点 ID
- 当前场景标签
- 玩家已做关键选择
- 玩家已解锁剧情标记
- 玩家已获得线索
- 玩家已获得道具
- 角色关系状态
- 玩家属性值
- 当前在场角色
- 已知事实
- 未知真相
- 禁止提前泄露的信息
- 可触发结局池
- 当前可用的交互模式

### 12.2 为什么“已知事实”和“真实真相”要分开

在推理剧本中，系统必须区分：

- **真实世界状态**：真正发生了什么
- **玩家认知状态**：玩家已经知道什么
- **角色认知状态**：某 NPC 知道什么、会说什么、故意隐瞒什么

如果不区分，模型很容易把“作者知道的真相”直接说给玩家，导致推理失效。

### 12.3 角色状态也必须结构化

每个角色建议有：

- 基础设定
- 性格关键词
- 当前立场
- 对玩家态度
- 已暴露信息
- 禁止透露的信息
- 语言风格
- 可被说服阈值
- 对某些线索的反应规则

这样模型生成的对话才不会每轮都像不同的人。

## 13. 选择系统在接入 LLM 后如何变化

### 13.1 固定选项仍然保留

即使接入 LLM，也不能取消固定选项。  
固定选项依然是主线推进的骨架，作用包括：

- 控制叙事节奏
- 降低玩家输入成本
- 提供稳定的主线流转
- 保证关键节点有明确可测的结果

### 13.2 新增“自由行动”入口

在适合的节点上，固定选项旁边可以增加：

- `自定义行动`
- `继续追问`
- `尝试其他调查方式`
- `输入你的做法`

这样玩家知道这个场景是“可扩展互动”的。

### 13.3 LLM 可以生成新的临时选项

系统还可以在生成后动态返回新的后续选项，例如：

玩家输入：“我故意说错案发时间，看他会不会纠正我。”

模型返回后，系统生成临时选项：

- 继续顺着他的反应追问
- 当场揭穿他的慌乱
- 暂时不表态，记下异常

这类“生成式二级选项”会让玩家感觉剧情更活。

## 14. NPC 对话模式

这是 LLM 最容易体现价值的地方。

### 14.1 传统模式下的问题

纯固定台词的缺点是：

- 对话轮次有限
- 玩家只能点预设句子
- 很难产生“套话”“试探”“反问”“诱导”的感觉

### 14.2 接入 LLM 后的对话体验

平台可以支持：

- 自由提问
- 针对线索追问
- 根据关系值调整语气
- 根据玩家是否强势、温和、冷静来变化回应
- 同一句问题在不同剧情进度下得到不同答案

例如玩家问“你昨晚在哪里”，如果：

- 关系低：角色敷衍、回避
- 关系中：角色给出部分信息
- 拿到关键证据后：角色会慌乱、改口、解释

### 14.3 NPC 对话的边界控制

为了稳定：

- 对话只能围绕当前场景与已知角色
- 模型不可直接泄露核心谜底
- 对关键证据只能在满足前置条件后响应
- 每个角色需绑定话术风格与可说范围

---

## 15. 调查与自由探索模式

这是第二个非常适合加入 LLM 的模块。

### 15.1 固定调查与自由调查并存

传统玩法是：

- 点击“调查桌面”
- 获得线索“A”

加入 LLM 后，可以升级为：

- 系统给出可调查区域
- 玩家输入自己具体想看的东西
- 模型根据该区域和世界状态生成更细反馈

例如玩家不是简单点“调查桌面”，而是输入：

- “我看信封火漆章上的纹样”
- “我想摸一下桌面，看是不是刚擦过”
- “我把照片翻到背面看看有没有字”

这样体验会比纯按钮强很多。

### 15.2 调查反馈的结果类型

一次 LLM 调查反馈可能产生：

- 普通文本反馈
- 新线索
- 线索补充描述
- 属性变化
- 可追问对象更新
- 新选项出现
- 无收获但强化氛围

### 15.3 防止玩家无限乱试

为了避免玩家不停输入无意义内容，系统可以加入：

- 每节点探索次数上限
- 场景可交互目标提示
- 输入意图识别失败时给出引导
- “当前场景中更值得调查的是……”之类的回导文案

---

## 16. 属性、线索、道具、关系系统如何与 LLM 结合

### 16.1 属性系统与 LLM

模型生成内容时应读取属性值。例如：

- 观察高：会生成更丰富的视觉细节
- 推理高：系统会额外给出推断倾向提示
- 口才高：对话判定更容易成功
- 行动高：危险场景中成功率更高

### 16.2 线索系统与 LLM

模型必须基于玩家已获得的线索来生成反馈，而不是凭空追加。  
例如同样是追问某角色：

- 没拿到“旧怀表”时，对话很普通
- 拿到后再问，角色反应会更明显

### 16.3 道具系统与 LLM

玩家可以用自由输入指定道具用途：

- “我把通行证递给门卫”
- “我出示旧照片试探她”
- “我拿怀表和信纸进行比对”

系统识别后，调用模型生成符合上下文的反应。

### 16.4 关系系统与 LLM

关系值不是只影响结局，还应实时影响：

- NPC 说话语气
- 是否愿意补充细节
- 是否愿意替玩家冒风险
- 是否触发专属支线

这会让玩家明显感受到“之前做过的事正在影响现在”。

---

## 17. 章节推进模式在接入 LLM 后如何变化

### 17.1 主线章节仍然固定

章节顺序和关键节点不建议完全动态化，原因是：

- 好内容需要设计
- 节奏需要控制
- 真相需要铺垫
- 结局条件需要稳定

因此：

- 第一章负责建立悬念
- 第二章开放调查
- 第三章加深冲突
- 第四章进入回收与偏转
- 第五章完成结局判定

这个主结构应保持稳定。

### 17.2 章节内部可以更动态

动态化更适合发生在章节内部，例如：

- 某段对话写法变化
- 某个支线触发方式变化
- 调查顺序不同导致反馈不同
- 过场演出根据玩家风格个性化

这样既有“AI 很灵活”的感受，又不会破坏作者设计。

---

## 18. 存档与继续游戏在 LLM 场景下的要求

接入 LLM 后，存档不再只是保存“当前节点 ID”，还必须保存“生成状态”。

### 18.1 建议存档内容

- 当前剧本 / 章节 / 节点
- 已做关键选择
- 已获得线索与道具
- 角色关系值
- 玩家属性值
- 已解锁分支标记
- 最近几轮 AI 对话摘要
- 当前场景的动态状态
- 当前可追问对象
- 临时生成选项记录

### 18.2 为什么要保存 AI 对话摘要

因为下一次调用模型时，不能只看节点 ID，还要知道玩家刚刚问过什么、角色已经说过什么。  
否则读档后角色会“失忆”，体验会很割裂。

### 18.3 建议用摘要而不是整段历史

为了控制上下文成本，建议保存：

- 关键对话摘要
- 已确认事实
- 未确认怀疑点
- 本场景互动结果

而不是把所有原始文本都塞回模型。

---

## 19. 结局系统在接入 LLM 后的设计

### 19.1 结局判定仍应规则化

即使中间过程用了大量 LLM，结局判定最好依然由规则引擎决定。  
即：

- 是否拿到关键线索
- 是否进入隐藏分支
- 某角色关系是否达到阈值
- 是否触发某关键事件
- 某几个核心选择是否成立

由这些结构化条件共同判定结局。

### 19.2 LLM 在结局页中的作用

模型更适合用于：

- 生成结局描述的个性化版本
- 生成本轮故事总结
- 生成“你离真结局差在哪里”的复盘提示
- 生成角色视角的后记

也就是说：

> **规则决定你得到哪个结局，LLM 决定这个结局如何更生动地呈现给你。**

---

## 20. 路线图与生成式复盘模式

这是平台很有特色的亮点功能。

### 20.1 路线图负责结构化展示

路线图负责展示：

- 你走过哪些节点
- 哪些分支未解锁
- 哪些结局已获得
- 哪些隐藏路线未探索

### 20.2 LLM 负责生成叙事化复盘

在路线图之外，系统可以生成一段“本轮故事回顾”，例如：

- 你这一轮选择更偏谨慎
- 你更相信角色“墨染”，因此错过了某条反证线索
- 你在第二章多次优先调查人物而非场景，因此关系收益高但证据不足
- 你距离真结局只差关键道具“旧怀表”

这种复盘能显著提升玩家对自己路线的理解。

### 20.3 多周目推荐

平台还可以让 LLM 根据玩家本轮路径自动给出：

- 推荐下一次优先探索的支线
- 哪个角色值得重点接触
- 哪个遗漏线索最关键

这样复玩动机会更强。

---

## 21. 一个包含 LLM 实时互动的完整游玩示例

### 21.1 进入平台

用户在首页看到“雾都迷案”，卡片标签包括：

- 悬疑推理
- 多结局
- AI 实时互动

用户进入详情页，看到说明：

> 本剧本支持自由追问角色、动态调查与生成式复盘。

### 21.2 进入第一章

玩家开始第一章“血色雨夜”。  
系统展示背景图、文本、当前进度与属性状态。

### 21.3 先走固定选项

玩家点击：

- 前往案发现场，仔细搜查

系统进入调查节点，获得线索“破损的伞骨”，观察 +1。

### 21.4 使用自由输入调查

此时系统开放“自定义行动”。  
玩家输入：

> 我想检查那封信的火漆章，看看是不是某个家族纹章。

系统读取当前场景与已获得线索，调用 LLM，返回：

- 火漆章边缘磨损严重，但中央图案仍像是某种家徽残片
- 你隐约觉得这与上城区旧贵族家族有关
- 新增线索：残缺纹章印记

### 21.5 与 NPC 实时对话

接下来玩家找到一名目击者，输入：

> 我先不直接问案发时间，我想先问他为什么一直盯着那座钟楼。

系统根据角色设定与关系状态生成回答。  
目击者没有直接交代案情，但暴露出他对钟楼异常敏感。  
系统进一步弹出生成式二级选项：

- 继续追问钟楼
- 转问他昨夜见到的人
- 假装相信他，换个角度试探

### 21.6 中途存档

系统不仅保存节点，还记录：

- 当前已获线索
- 对话摘要
- 目击者对玩家的警惕度
- 当前可继续追问的话题

### 21.7 达成结局并生成复盘

本轮结束后，规则引擎判定玩家进入普通结局“迟来的真相”。  
结局页中，LLM 生成本轮回顾：

> 你在这一轮中更依赖人物问询，而非现场深挖，因此较早建立了与目击者的信任，却错过了第二章可发现的关键物证。你逐步逼近真相，却在最终指认时缺少足够支撑，导致真相虽接近，却无法完整闭合。

这比单纯提示“少了一条线索”更有故事感。

---

## 22. 从产品角度总结新的操作模式

加入 LLM 后，平台的操作模式可以概括为：

> **玩家在章节化、规则化的叙事骨架中，通过固定选择、半开放输入和自由文本交互推动故事；系统基于世界状态调用 LLM 实时生成对话、调查反馈、支线过渡与个性化复盘，并由规则引擎负责分支控制与结局判定。**

这个模式相较传统剧情游戏，多了三层价值：

### 第一层：更真实的参与感

玩家不只是“点按钮”，而是真的可以尝试自己的做法。

### 第二层：更高的叙事密度

角色对话、调查反馈和支线过渡更丰富，不容易产生“文本空壳感”。

### 第三层：更强的复玩驱动

因为玩家的输入方式不同、互动顺序不同、追问风格不同，每一轮体验差异会更大。

---

## 23. 开发落地建议

为了真正把这个模式做出来，建议从系统层分成四层实现。

### 23.1 内容层

结构化维护以下对象：

- Script
- Chapter
- StoryNode
- Choice
- Clue
- Item
- Character
- Ending
- SaveRecord
- WorldState
- PromptTemplate

### 23.2 规则层

规则层负责：

- 节点切换
- 条件判断
- 线索发放
- 属性变化
- 关系变化
- 结局判定
- LLM 调用前后的一致性控制

### 23.3 LLM 服务层

LLM 服务层负责：

- 玩家输入意图识别
- 场景化提示词拼装
- 角色说话风格控制
- 剧情反馈生成
- 结构化输出解析
- 安全审核与幻觉防护
- 生成摘要与复盘

建议输出格式尽量结构化，例如：

```json
{
  "narration": "……",
  "dialogue": [
    {"speaker": "目击者", "text": "……"}
  ],
  "clue_updates": ["残缺纹章印记"],
  "relation_updates": {"目击者": -1},
  "attribute_updates": {"观察": 1},
  "new_choices": [
    "继续追问钟楼",
    "转问昨夜见到的人"
  ],
  "next_node_id": "node_1_4_followup"
}
```

### 23.4 前端交互层

前端需要支持：

- 固定选项按钮
- 自由输入框
- 动态对话展示
- 状态面板
- 线索 / 道具 / 关系查看
- 存档与读档
- 路线图与复盘展示

---

## 24. MVP 版本建议

如果先做最小可用版本，建议优先实现：

1. 首页与剧本详情页
2. 固定章节式剧情阅读
3. 基础分支选择机制
4. 自动存档
5. 多结局判定
6. NPC 实时问答
7. 调查场景自由输入
8. 结局后的生成式复盘

第二阶段再扩展：

- 更复杂的角色关系系统
- 动态支线生成
- 创作者中心接入 AI 剧本辅助
- 个性化推荐系统
- 社区攻略自动摘要
- 长上下文记忆优化

## 25. 结语

“谜语剧场”加入 LLM 实时生成剧情后，不再只是“带分支的视觉小说”，而是更接近一种：

> **可控世界中的半开放叙事游戏。**

它的最佳形态不是完全自由生成，也不是完全固定剧本，而是：

- 用作者保证世界观、悬念、节奏和结局质量
- 用规则系统保证一致性和可控性
- 用 LLM 提供真实、细腻、高密度的即时互动

最终让玩家获得的体验是：

> **我不是在看一个已经写完的故事，我是在故事内部进行行动，而故事正在对我的行为做出回应。**
