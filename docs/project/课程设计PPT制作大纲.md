# 谜语剧场课程设计 PPT 制作大纲

## 1. 使用建议

- 适用场景：课程设计汇报、结课答辩、项目展示。
- 建议页数：12 到 14 页。
- 建议时长：8 到 12 分钟。
- 讲述顺序：选题背景 -> 需求分析 -> 系统方案 -> 核心实现 -> 运行效果 -> 创新与不足 -> 总结展望。
- 制作原则：一页只讲一个核心问题，少堆字，多放结构图、页面截图、流程图和结果图。

## 2. 汇报总逻辑

- 第一部分回答“为什么做”：说明互动叙事产品的价值和课程设计选题意义。
- 第二部分回答“做了什么”：说明平台目标、功能范围和业务流程。
- 第三部分回答“怎么做”：说明前端架构、剧情引擎、LLM 协作、数据存储和模块设计。
- 第四部分回答“做成什么样”：展示页面效果、故事内容、测试结果和当前成果。
- 第五部分回答“还有什么问题”：说明不足、边界和后续优化方向。

## 3. 逐页制作大纲

### 第 1 页：封面页

- 标题建议：谜语剧场——基于 Web 与受控 LLM 互动的剧情交互游戏平台设计与实现。
- 副标题建议：课程设计答辩 / 项目汇报。
- 必放信息：姓名、学号、班级、课程名称、指导教师、日期。
- 版式建议：使用项目首页视觉或品牌 Logo 做主视觉，保持黑金或沉浸式风格。
- 讲解重点：一句话点题，说明这是一个可运行的互动叙事游戏平台原型。

### 第 2 页：选题背景与研究意义

- 说明传统线性阅读和普通视觉小说的局限：互动弱、反馈少、复玩率不高。
- 说明用户对多结局、角色关系推进和沉浸式叙事体验的需求。
- 点出本项目研究意义：验证“固定剧本骨架 + LLM 动态互动反馈”的可行性。
- 建议素材：行业趋势关键词、互动叙事产品示意图、问题对比图。
- 讲解重点：交代为什么这个题目适合作为课程设计。

### 第 3 页：项目目标与建设内容

- 项目目标：构建一个支持多剧本、多分支、多结局和有限自由交互的 Web 平台。
- 当前建设内容：多剧本入口、剧情引擎、图鉴、结局回顾、存档、登录、LLM 设置。
- 可补一句：本项目既有平台层，也有剧情层和互动层。
- 建议素材：目标拆解图或三层结构图。
- 讲解重点：明确不是单页 Demo，而是可扩展的平台原型。

### 第 4 页：需求分析与用户痛点

- 用户痛点 1：难以快速找到适合自己的优质剧情内容。
- 用户痛点 2：普通文字冒险游戏互动形式单一，反馈不够细。
- 用户痛点 3：缺少结局收集、路线复盘和多周目驱动力。
- 用户痛点 4：传统项目展示往往只停留在 UI，不具备完整可玩闭环。
- 建议素材：用户痛点列表、需求到功能映射图。
- 讲解重点：说明每个功能模块都对应真实问题，不是随意堆功能。

### 第 5 页：系统总体方案

- 展示系统总体结构：前端展示层、运行时引擎层、后端服务层、数据存储层。
- 前端展示层：Vue 3 + Pinia + Vue Router，包含首页、剧本库、详情页、剧情页、结局页、社区页等。
- 运行时引擎层：story-engine.js（状态机、选项推进、结局判定）、perform-controller.js（VN 式逐句演出）、LLM 客户端。
- 后端服务层：Express + Prisma ORM，提供认证（JWT）、故事、存档、评论四组 RESTful API。
- 数据存储层：SQLite 数据库（User、Story、SaveSlot、Comment），localStorage 补充本地存储。
- 内容配置层：story pack 配置文件 + 数据库 packData JSON 双层方案。
- 建议素材：系统总体架构图。
- 讲解重点：让老师先建立完整技术全景图，强调前后端分离与数据库化。

### 第 6 页：业务流程与核心玩法

- 流程建议：进入首页 -> 浏览剧本 -> 进入详情与设置 -> 开始故事 -> 做出选择 / 探索 / 对话 -> 触发结局 -> 回顾与重玩。
- 当前支持的互动模式：固定选项、动态扩展操作、自由探索、NPC 对话、自由输入兜底。
- 说明本项目的核心体验是“剧情推进 + 状态变化 + 有限自由互动”。
- 建议素材：业务流程图、玩家路径图。
- 讲解重点：把“好玩在哪里”说清楚。

### 第 7 页：功能模块设计

- 平台层：首页、剧本库、排行榜、社区、创作工坊、个人中心。
- 剧情层：多剧本内容包、scene 配置、线索与结局系统。
- 互动层：对话、探索、自由输入、VN 式演出。
- 数据层：自动存档、6 个本地存档位、游客 / 注册登录、文件型云存档模拟。
- 建议素材：模块分层图或功能脑图。
- 讲解重点：按层拆功能，结构会比逐页介绍更清楚。

### 第 8 页：关键技术与核心实现

- 技术栈：Vue 3 + Pinia + Vue Router（前端）、Express + Prisma + SQLite（后端）、Vite 6（构建工具）、npm workspaces（monorepo 管理）。
- 叙事结构：使用 stage / scene 模型驱动剧情推进，引擎自动构建 VN 对话序列（buildDialogueLines）。
- 表演系统：WebGAL 风格的 perform-controller 状态机，支持逐句播放、打字机效果、对话历史。
- 数据库设计：4 张核心表（User、Story、SaveSlot、Comment），Story 表包含 packData JSON 字段存储完整故事内容。
- API 设计：RESTful 风格，认证（JWT）、故事列表/详情、云存档 CRUD、评论 CRUD。
- 建议素材：技术栈图、数据库 ER 图、关键数据流示意图。
- 讲解重点：说明项目是前后端分离的完整工程，不只是界面展示。

### 第 9 页：LLM 协作机制设计

- 说明 LLM 在项目中的角色：增强探索和对话反馈，而不是随意生成整条主线。
- 当前限制机制：sceneCard、visualState、hiddenTruths、forbiddenReveals、presentCharacters。
- 当前接入方式：浏览器直连 OpenAI 兼容接口，或通过本地后端代理。
- 降级策略：当 LLM 不可用时，自动回退到内置模板反馈。
- 建议素材：受控生成流程图。
- 讲解重点：强调“可控”而不是“完全放给模型生成”。

### 第 10 页：重点案例展示——《听晚》

- 简述《听晚》的题材：都市恋爱、久别重逢、合租心动。
- 说明当前接入范围：前四章、13 个 scene。
- 展示其配置亮点：sceneCard、visualState、角色话题、线索库、多结局。
- 可说明素材准备：已补充背景、角色、音效的生成提示词文档。
- 建议素材：剧情卡片、分场结构图、角色关系简图。
- 讲解重点：用一个具体案例证明系统不是空壳。

### 第 11 页：系统运行效果展示

- 展示首页、剧本库、详情页、剧情页、图鉴页、结局页截图。
- 如果页面较多，建议做成 2 行拼图版式，不要一页只放一张图。
- 每张图下面只写一句功能说明，例如“剧情图鉴支持查看分支与结局完成度”。
- 建议素材：运行截图、录屏二维码或演示链接。
- 讲解重点：让老师直观看到“已经做出来了”。

### 第 12 页：测试结果与当前成果

- 当前已内置 5 个故事包，全部入库并通过 API 可查询。
- 当前前后端分离：Vue 3 前端 + Express 后端，数据库存储用户、存档、故事、评论。
- 当前包含首页到结局回顾的主闭环页面。
- 当前支持 6 个本地存档位 + 数据库云存档。
- 当前支持 JWT 认证（注册 / 登录 / 游客）。
- 当前核心测试结果：62 项测试通过，0 项失败。
- 建议素材：测试结果截图、数据库表结构截图、API 接口列表、功能完成度统计图。
- 讲解重点：项目不仅能演示，还有完整后端与数据持久化能力。

### 第 13 页：创新点、特色与不足

- 特色 1：前后端分离架构，Vue 3 + Express + Prisma + SQLite，具备真实数据持久化能力。
- 特色 2：多剧本内容包与统一引擎解耦，故事完整入库，API 与本地双链路。
- 特色 3：固定剧情主线与 LLM 动态反馈结合，受控生成机制（sceneCard / forbiddenReveals）。
- 特色 4：WebGAL 风格 VN 演出系统，支持逐句播放、打字机、回顾、回滚。
- 特色 5：支持结局收集、图鉴、多周目，复玩路径完整。
- 当前不足：部分平台页仍为演示态，SQLite 不适合生产级部署，美术与音频资源未完全落地，游戏运行时仍依赖前端本地引擎代码。
- 建议素材：优点与不足对照图。
- 讲解重点：主动讲不足，会显得分析更完整。

### 第 14 页：总结与展望

- 总结项目价值：实现了从剧本入口到交互叙事再到结局回顾的完整原型闭环。
- 总结技术价值：验证了受控 LLM 在互动叙事中的辅助作用。
- 展望方向：接入真实素材资源、完善创作工坊、升级用户系统、扩展社区和数据能力。
- 结束语建议：感谢老师聆听，欢迎提问。
- 讲解重点：最后一页不要再堆新信息，以收束为主。

## 4. 演示部分建议

- 如果答辩允许现场演示，建议只演示 3 个关键点：首页切换剧本、剧情页选择推进、结局页回顾。
- 现场演示不要太长，控制在 1 分钟到 2 分钟。
- 优先展示已经最稳定的路径，例如《听晚》或默认故事包。
- 演示前准备好固定存档，避免临场操作过长。

## 5. PPT 视觉制作建议

- 主色建议沿用项目当前的黑金、深蓝灰和暖光配色。
- 标题尽量统一格式，例如“项目背景”“系统方案”“关键实现”。
- 每页正文建议不超过 6 行，每行不超过 18 个字。
- 有结构内容就画图，不要把流程图写成大段文字。
- 截图页尽量加标注框，避免老师看不出重点。

## 6. 答辩常见问题预案

### 问题 1：为什么选择 Vue 3 + Express + SQLite 这套技术栈？

- 回答建议：Vue 3 组件化开发效率高，Pinia 状态管理适合复杂游戏状态；Express 轻量灵活，配合 Prisma ORM 可快速建模；SQLite 零配置适合课程设计阶段，后续可无缝迁移到 PostgreSQL。整体技术栈兼顾开发效率与工程规范。

### 问题 2：LLM 会不会让剧情失控？

- 回答建议：项目没有把主线完全交给模型，而是通过 sceneCard、visualState、forbiddenReveals 等约束模型输出，LLM 只负责增强局部互动反馈。

### 问题 3：项目的创新点是什么？

- 回答建议：创新点在于把多剧本平台、剧情引擎、有限自由交互和受控 LLM 机制结合起来，形成了一个可演示、可扩展的互动叙事平台原型。

### 问题 4：项目目前最大的不足是什么？

- 回答建议：目前部分平台页面仍是演示态，数据库为本地 SQLite 不适合生产部署，美术与音频资源还没有完全接入，游戏运行时仍依赖前端本地引擎代码。但主体验闭环、数据持久化和 API 服务已经跑通。

## 7. 最终建议

- 若老师更重视“系统设计”，就多讲第 5 页到第 9 页。
- 若老师更重视“成果展示”，就多讲第 10 页到第 12 页。
- 若汇报时间不足，可把第 10 页和第 11 页合并，把第 12 页和第 13 页合并，压缩成 12 页版本。
- 正式制作 PPT 时，建议先按本大纲搭骨架，再填截图和图表，不要反过来边做边想结构。
